## 1. 发现并修复的缺陷（3 个，均前端，已验证）

> 均由深度功能测试实测暴露；修复文件 `web/{core,ui-native/flow}/design-workbench.js`（双份字节同步）。

### 🔴 Bug A：从浮层保存/发布子流程后，子画布被销毁

- **现象**（实测 `T1-overlay-survives` 初测 `shapes=0`）：在子流程编辑器里点「保存草稿」/「发布」后，子流程画布变空（图元全丢），浮层虽在但无法继续编辑。
- **根因**：`subSave`/`subPublish` 收尾调 `refreshView('property')`——那是**整个属性区重渲**，会重建 `[data-subflow-canvas]` DOM 节点，销毁其上的 bpmn-js 实例。
- **修复**：改为 `refreshSubEditor()`（就地刷新侧栏/属性/面包屑，**绝不动画布 DOM**，与主设计器 `refreshContentChrome` 保护主画布同思路）。
- **验证**：保存/发布后 `shapes=13`，浮层+画布存活；发布产版本（v→v+1）。

### 🔴 Bug B：新建子流程变体 key 撞车（都叫 `new_process`）

- **现象**（实测 `T2-newkey-not-newprocess` 初测 `key=new_process`）：为某组织「新建变体」时，空白模板的 process id 恒为 `new_process`，后端按 process id 派生定义 key → 每个新子流程都叫 `new_process`，**相互覆盖 / 撞主流程草稿**。
- **根因**：`subSave` 直接把 `EMPTY_DIAGRAM`（id=`new_process`）存库，未像主设计器 `doSaveAs` 那样改写 process id。
- **修复**：新增 `subXmlWithUniqueKey()`——新子流程存库前，若 process id 仍是默认 `new_process`（或撞已有定义），改写成有意义且唯一的 key（`{calledKey}_{org}`，如 `fin_review_branch_gz`）；已有真 key 的子流程迭代存版本不动 id。附带修「首存后子画布仍持旧 id → 重存又生成新 key 重复建定义」：首存后重载已存版本，使后续保存迭代同一 key。
- **验证**：新变体 key=`fin_review_branch_gz`（非 new_process）；首存 +1 定义；**重存不重复建**（31→31）；自动绑定到 branch_gz。

### 🟠 Bug C：关闭子流程编辑器后，主属性面板错乱 + 关闭被触发多次

- **现象**（实测）：从 callActivity 打开子编辑器再关闭后，主属性面板回落到「流程属性」（而非停在该 callActivity），「编辑子流程」按钮消失；且调试发现单次点关闭触发了 **6 次** `closeSubEditor`。
- **根因（两个叠加）**：
  1. 子编辑器的 modeler 把共享的 `state.selectedElement` 改成了子流程节点，关闭后未恢复主画布选中的 callActivity。
  2. `refreshSubEditor`（就地刷新）每次都重绑 `[data-sub-close]` 等**持久控件**（它们在未重渲的 head/toolbar 里），监听器逐次累积——切几次变体后一次点击=多次关闭。
- **修复**：
  1. `openSubEditor` 记住主选中元素 `se.mainSelected`；`closeSubEditor` 恢复 `state.selectedElement` 并经主 modeler `selection.select` 同步。
  2. 拆分绑定：`bindSubEditorPersistent`（close/name/工具栏，只在整块渲染绑**一次**）+ `bindSubEditorVolatile`（变体/新增变体，随就地刷新重绑）——彻底消除累积。
- **验证**：切变体后单次关闭 → 浮层消失、主属性面板显示「子流程调用 CallActivity · fin_review」、「编辑子流程」按钮在；关闭仅触发 1 次。

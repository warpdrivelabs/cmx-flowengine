## 二、测试架构

### 2.1 两个路由维度（一个内建、一个任意字典）

| 维度 | dimKey | 数据源 | 层级形态 | 物化路径 | 分隔符 |
|------|--------|--------|---------|---------|--------|
| **组织机构**（内建） | `org` | `cmx_org`（IAM 库） | 自分级树 | `path`（id 段） | `/`（斜杠） |
| **产品**（任意字典） | `product` | `cf_product`（IAM 库，对标 DCT cf_* 表） | 自分级树 | `full_path`（code 段） | `.`（点） |

产品维度通过环境变量注册（**不改一行代码即可新增任意维度**）：
```
FLOW_ROUTING_DIMENSIONS='[{"dimKey":"product","name":"产品","table":"cf_product",
  "idCol":"id","pathCol":"full_path","delim":".","nameCol":"name","parentCol":"parent_id"}]'
```

### 2.2 组织机构维度树（cmx_org，斜杠路径）

```
总部 zongbu (/zongbu)
├─ 北京财务部 fin_bj (/zongbu/fin_bj)
│   └─ 北京财务一组 fin_bj_g1 (/zongbu/fin_bj/fin_bj_g1)
└─ 上海财务部 fin_sh (/zongbu/fin_sh)
广州分公司 branch_gz (/branch_gz)   ← 独立根，不在总部下
```

### 2.3 产品维度树（cf_product，点路径，对标 DCT）

```
全部产品 ALL (ALL)
├─ 金融产品 FIN (ALL.FIN)
│   ├─ 储蓄卡 SAVE (ALL.FIN.SAVE)
│   └─ 信用卡 CREDIT (ALL.FIN.CREDIT)
└─ 保险产品 INS (ALL.INS)
    └─ 车险 CAR (ALL.INS.CAR)
```

### 2.4 主流程与挂载点

主流程 `reimburse_dual`（报销双维度主流程）——**两个挂载点各绑不同维度**：

```
开始 → 填报销单(apply) → ①预算审批 callBudget[dimKey=org]
                        → ②合规审查 callComp[dimKey=product]
                        → 出纳打款(pay) → 结束
```

- `callBudget` 写 `cmx:calledKey="budget_appr" cmx:dimKey="org"` —— 按**组织**路由
- `callComp` 写 `cmx:calledKey="prod_compliance" cmx:dimKey="product"` —— 按**产品**路由

### 2.5 子流程（8 个）

| 维度 | 子流程 | 用途 |
|------|--------|------|
| org | budget_hq / budget_bj / budget_sh / budget_branch | 总部/北京/上海/分公司 各自预算审批 |
| product | comp_generic / comp_finance / comp_credit / comp_insurance | 通用/金融/信用卡/保险 各自合规审查 |

## 七、测试过程中发现并处理的问题（非功能缺陷）

测试执行过程中遇到 3 个**测试脚本层面**的问题（均为测试环境/脚本适配，**非路由功能缺陷**），已全部解决，记录如下以证测试严谨性：

1. **办理任务需用户身份**：`FLOW_AUTH_MODE=jwt` 下办理任务须 JWT 身份。改用 `FLOW_AUTH_MODE=off` + `X-User` 头指定办理人。
2. **X-API-Key 会激活鉴权**：auth-off 下若同时带 `X-API-Key`，鉴权中间件被激活反而要求 JWT。修正为 auth-off 下只用 `X-User` 头。
3. **子流程办理人各异**：各子流程 userTask 的 assignee 不同（u_budget_hq / u_comp_fin…），办理时须按各任务的 assignee 传 `X-User`，否则「无权办理」。脚本 `drain_child` 改为动态读取 assignee。

> 三个问题都在**测试脚本与鉴权模型的适配**，路由解析逻辑（引擎侧）自始至终正确——阶段3 组织维度在修脚本前就已全绿，印证功能本身无缺陷。

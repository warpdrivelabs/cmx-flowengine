cmx-flow 流程引擎 · 数据库表结构文档

M1 顺序审批 + M2 并行网关/历史归档 + M3 多实例会签·或签/实例取消 + M2.5 边界定时器 · 运行态/历史态分离（RU/HI）

数据库：PostgreSQL schema：public 表数量：7（RU 5 + HI 2） 前缀：cmx_flow_ 外键：无（索引替代）

概述

流程引擎把运行态拆成 RU（运行态） 与 HI（历史态） 两组表，对齐 Flowable 的 RU/HI 分离。 RU 五张表——实例（主体 + 变量）、令牌（流经流程图的执行指针）、任务（用户任务，等待态外化）、 多实例域（会签/或签的计数账本）、定时器作业（边界定时器到期表）——构成一个聚合，引擎以 「实例 + 其全部令牌 + 其任务 + 其多实例域 + 其定时器作业」为原子单元读写。 每个 BPMN 等待态对应一次数据库事务提交，即「等待态即提交点」。实例进入终态时，同一事务内幂等归档到 HI 两张历史表。

  • 所有表以 cmx_flow_ 前缀命名，符合系统基础表命名约束。
  • 不使用外键约束：保留关联字段（instance_id / token_id）并用索引替代。
  • 主键均为 VARCHAR(64)，承载引擎生成的 UUID 字符串。
  • 所有时间列为 TIMESTAMPTZ（带时区），对应 Rust 侧 DateTime<Utc>。
  • 实例变量以 JSONB 存储，天然对齐流程作用域的动态 KV。
  • M2 新增：令牌 JOINING 状态（并行网关合流等待）+ 两张历史表（含存续/办理时长）。
  • M3 新增：cmx_flow_mi_scope 多实例执行域表（会签/或签）+ cmx_flow_task.element_value 列；实例取消激活 TERMINATED 终态归档。
  • M2.5 新增：cmx_flow_job 定时器作业表（边界定时器）；可注入时钟 + 显式 trigger_due_timers() 推进，find_due_jobs 按 due_at 跨实例扫描到期作业。

逻辑关系（无物理外键）

cmx_flow_instance （流程实例 · 聚合根 · RU） │ id (PK) │ ├──< cmx_flow_token token.instance_id → instance.id （一实例多令牌） │ │ id (PK) │ │ │ └──< task.token_id → token.id （一令牌一等待任务） │ ├──< cmx_flow_task task.instance_id → instance.id （一实例多任务） │ ├──< cmx_flow_mi_scope scope.instance_id → instance.id （M3 · 会签/或签账本） │ node_bpmn_id 关联同节点的子任务/子令牌 │ └──< cmx_flow_job job.instance_id → instance.id （M2.5 · 定时器作业，挂在宿主令牌上） 实例终态归档（同事务，幂等 upsert）： cmx_flow_instance ──► cmx_flow_hi_instance （HI · 含 duration_ms） cmx_flow_task (completed) ──► cmx_flow_hi_task （HI · 含 duration_ms） 关联全部通过普通列 + 索引实现，无 FOREIGN KEY 约束。

cmx_flow_mi_scope多实例执行域表

多实例（multiInstance）把一个逻辑 userTask 展开成多个子任务：并行 = 会签（齐头并进），顺序 = 或签（逐个办理）。本表记账每次展开：总数 / 已完成 / 顺序游标 / 完成条件。随聚合快照全删重插——故进程重启后 completionCondition 仍能基于恢复的计数正确求值。

#列名类型可空默认值说明
1idPKvarchar(64)NOT NULL—域唯一标识（UUID）
2instance_idIDXvarchar(64)NOT NULL—所属实例 id（逻辑关联 instance.id）
3node_bpmn_idvarchar(128)NOT NULL—对应 multiInstance 节点 BPMN id（关联同节点子任务/子令牌）
4sequentialbooleanNOT NULLfalsetrue=顺序(或签)；false=并行(会签)
5totalintegerNOT NULL—子实例总数（nrOfInstances）
6completedintegerNOT NULL0已办结子实例数（nrOfCompletedInstances）
7next_indexintegerNOT NULL0顺序模式下一个待展开元素下标；并行模式恒 = total
8collectionjsonbNOT NULL'[]'展开用的元素快照（定格避免中途变量被改）
9element_varvarchar(128)NULL—子任务携带当前元素的变量名（elementVariable）
10completion_conditionvarchar(512)NULL—完成条件表达式（命中即提前收口剩余子实例）
11finishedbooleanNOT NULLfalse本域是否已收口（完成条件命中或全部完成）

完成条件内置变量

求值时以实例变量为底叠加（不落库）：nrOfInstances / nrOfCompletedInstances / nrOfActiveInstances。例：${nrOfCompletedInstances/nrOfInstances >= 0.5}（过半即通过）、${rejected == true}（任一驳回即终止或签）。

7 列 · 3 索引 · M2.5
cmx_flow_job定时器作业表

边界定时器的「到期待触发」表。令牌到达挂有边界定时器的 userTask 时，为每个定时器建一条作业（记 due_at）。引擎用可注入时钟 + 显式 trigger_due_timers() 推进（不自带后台线程）：find_due_jobs 按 due_at 索引跨实例扫描到期作业，触发后令牌走定时器出边（中断型）或发旁路令牌（非中断型）。令牌离开宿主即撤销作业。

#列名类型可空默认值说明
1idPKvarchar(64)NOT NULL—作业唯一标识（UUID）
2instance_idIDXvarchar(64)NOT NULL—所属实例 id（逻辑关联 instance.id）
3token_idvarchar(64)NOT NULL—挂载令牌 id（停在宿主 userTask）；令牌离开即撤销
4boundary_bpmn_idvarchar(128)NOT NULL—触发时令牌要去的边界事件节点 bpmn_id
5cancel_activitybooleanNOT NULLtruetrue=中断型（中断宿主任务）；false=非中断型（发旁路令牌）
6due_atIDXtimestamptzNOT NULL—到期时刻（宿主到达时刻 + 时长）
7created_attimestamptzNOT NULL—作业创建时间

时长格式

来自 BPMN <timeDuration> 的 ISO 8601 相对时长（PT24H/PT30M/P1D 等），编译期手写解析为秒。M2.5 仅支持 timeDuration（相对时长），不支持 timeDate（绝对时刻）/ timeCycle（循环）。

Rust 类型对应

  • varchar ↔ String；可空列 ↔ Option<String>
  • timestamptz ↔ DateTime<Utc>；可空 ↔ Option<DateTime<Utc>>（写入 NULL 须带类型标记 NullTyped(Timestamp)）
  • bigint ↔ i64；可空 ↔ Option<i64>（写入 NULL 须 NullTyped(Int)）
  • jsonb ↔ Variables（内部 BTreeMap<String, serde_json::Value>）
  • boolean ↔ bool
  • state 文本列 ↔ Rust 枚举 InstanceState / TokenState（SCREAMING_SNAKE_CASE 字符串）

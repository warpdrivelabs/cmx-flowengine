## 四、缺陷与修复

### D-1（既存 bug，真机 E2E 发现并修复）：空 `dimensions` jsonb 裸 NULL 序列化失败

- **现象**：不带 `orgId` 发起实例 → `500 存储层错误: 事务内执行失败: error serializing parameter 9`。
- **根因**：`mapping.rs::dimensions_param` 对空维度返回裸 `DataValue::Null`；tokio-postgres 对 jsonb 列绑裸 NULL 报序列化错（参数 0-indexed，param 9 = 第 10 个值 = dimensions jsonb 列）。**属会话前的子流程维度路由代码**，非本次新功能引入。
- **为何测试没抓到**：in-memory store 不序列化参数；PG 集成测试 `#[ignore]`（需活库）默认不跑。**唯有真机 E2E 能暴露**。
- **修复**：`dimensions_param` 空维度改用 `DataValue::NullTyped(SqlTypeMarker::Json)`（与 `opt_ts`/`opt_json` 一致的带类型 NULL）。另将 `opt_text` 的 None 改为 `NullTyped(Text)` 作防御性加固。修复后不带 orgId 发起成功。

### D-2（过时单测）：`rejects_non_timer_boundary_event`

- 见上「回归」小节，已修正。
